Les conversations de Strike Commander

Comment le jeu joue une conversation : le script de CONV.PAK, les scènes de groupe, le gros plan avec sa tête parlante, les yeux et la bouche, la question « Accept / Reject », puis la voix de la version CD-ROM et les corrections à porter dans libRealSpace.

Toutes les images de cette page sont composées avec les données du jeu, selon les règles lues dans le code (outil tools/conv_doc_images.py). La référence complète, avec les citations d'assembleur, est analysis/CONV_SYSTEM.md.

  • 241 scripts non vides
  • 1 717 CLOSEUP
  • 86 scènes de groupe
  • 62 images par visage
  • 10 images de scène par seconde

Lancement

Le script de partie lance une conversation par PLAY_CONV n (entrée n de CONV.PAK), jouée par Gameflow_PlayConversation_4AAAB → Conv_Construct_59B67 → Conv_PlayScript_5AA4E. Le code en lance aussi quatre lui-même :

  • 254 si les avions perdus au total dépassent 16 (« The insurance company has dropped our policy ») ;
  • 255 si l'argent devient négatif (Gameflow_CheckLossConversations_50645) ;
  • 252 ou 253 par PLANES_LOST_CONV, si des avions ont été perdus pendant la mission.

CONVDATA.IFF

  • FORM BACK : INFO = nom (8 octets) ; DATA = suite d'éléments de 5 octets, dessinés dans l'ordre : octet source (0 = CONVSHPS / CONVPALS, 1 = OPTSHPS / OPTPALS), octet image, octet palette, mot signé = position verticale de l'élément.
  • FORM FACE, FIGR, PFIG, FCPL, FGPL : nom (8 octets) + un octet, numéro d'image ou de palette.

Format d'un script

Une suite de commandes. Chaque commande = 1 octet, puis ses champs. Entiers petit-boutistes. « nom » = 9 octets complétés par des 0 ; « chaîne » = texte terminé par un 0.

Deux formats. Le format CD (données de BIGTRE.TRE) a, devant chaque texte, une chaîne de plus : l'identifiant de voix (3gw009, 1ai021… ; chaîne vide quand la réplique n'a pas de voix). Le format disquette ne l'a pas. Le reste est identique. Les tableaux notent ce champ [voix].

Grammaire

script     := commande*
commande   := GROUP_SHOT décor figurant* réplique*
            | CLOSEUP gros_plan suite*
            | SHOW_TEXT couleur texte                 (CD)
            | YESNOCHOICE_BRANCH2 mot
            | SELECT_WING octet octet
            | CHOOSE_WINGMAN | NOP_16 | NOP_18
figurant   := GROUP_SHOT_ADD_CHARACTER nom x y
réplique   := GROUP_SHOT_CHARACTER_TALK nom x y couleur texte
            | SHOW_TEXT couleur texte
gros_plan  := visage image décor x y texte couleur
suite      := CLOSEUP_CONTINUATION texte
            | SHOW_TEXT couleur texte
            | YESNOCHOICE_BRANCH1 mot
texte      := [voix] chaîne

Exemple : proposition de mission (entrée 62)

Farnsworth propose le contrat ; YESNOCHOICE_BRANCH1 pose la question. Si le joueur refuse, le curseur saute la branche « accepter ».

CLOSEUP              far, image 22, mp1_cu   « Eight million dollars, with bonuses.  Do you accept? »
YESNOCHOICE_BRANCH1  159                      refus : saute 159 octets
CLOSEUP              far, image 255, mp1_cu  « Good.  I'll contact Virgil to close later.  Watch your back... »
CLOSEUP              far, image 14, mp1_cu   « ...it's dangerous out there. »
YESNOCHOICE_BRANCH2  78                       fin de la branche « accepter » : saute 78 octets
CLOSEUP              far, image 25, mp1_cu   « All right, but I'd reconsider, if I were you. »

Les 52 sauts des données tombent tous sur le début d'une commande. La réponse est rangée pour la partie ; le script de partie choisit la suite par IF_MISSION_ACCEPTED et IF_MISSION_REFUSED.

3

Scène de groupe (GROUP_SHOT)

Où l'on dessine

Dans une image hors écran de 320 × 200. Sa ligne 0 arrive à la ligne 24 de l'écran et seules les lignes 0 à 127 sont visibles (écran 24 à 151) ; la bande du bas (152 à 199) reçoit le texte. Une position (x, y) du script est donc à l'écran en (x, y + 24), l'image gardant ses propres décalages.

Ordre de dessin

  1. les éléments du décor, dans l'ordre du BACK, chacun en (0, y) ;
  2. les figurants (GROUP_SHOT_ADD_CHARACTER), image 0, dans l'ordre du script ;
  3. les personnages qui parlent (GROUP_SHOT_CHARACTER_TALK), image 0 puis la bouche pendant leur réplique.

Chaque image recouvre les précédentes là où ses segments de ligne passent (pas de XOR, pas de couleur transparente) : c'est l'ordre du script qui décide qui est devant.

Palette (une seule pour la scène)

  1. la palette de chaque élément du décor ;
  2. FGPL « normal » (CONVPALS 48) ;
  3. la palette PFIG du premier figurant seulement ; sans figurant, rien de plus.

Durées (disquette)

  • la scène tourne à 10 images par seconde ;
  • GROUP_SHOT_CHARACTER_TALK : une image par caractère du texte, sans attente après ;
  • SHOW_TEXT dans la scène : 40 images ;
  • une touche passe à la réplique suivante.

Bouche d'un personnage qui parle

Un caractère par image, sans règle de prononciation ni clignement. Bouche = chiffre de « 04302500000340143000353000 » + 1 pour les lettres a à z, aucune pour le reste. Images de bouche 1 à 6 :

abcdefghijklmnopqrstuvwxyz
15413611111451254111464111

Figures à 7 images (air1, stern1, airwing1…) : image 0 = corps, 1 à 6 = bouches. Les figures à 1 image (air3, stern2, virgil1…) ne peuvent servir que de figurants.

4

Gros plan (CLOSEUP)

Le texte de ces images est écrit avec une police quelconque, centré : la police du jeu n'est pas reproduite et sa position horizontale n'a pas été lue. Lignes de 30 caractères au plus, coupées aux espaces, à y = 156 + 15 × n sur l'écran.

Ordre de dessin, à la position de la commande

  1. les éléments du décor (BACK) ;
  2. image 0 du visage : la tête et le haut du corps ;
  3. l'image des yeux : l'image de base (l'octet « image »), ou 12 pendant un clignement ; rien pour 255 ;
  4. la bouche, rien si elle vaut −1 ;
  5. image 1 : la coiffure ;
  6. image 34 : les habits.

Palette

Palettes du décor, puis FCPL « normal » (CONVPALS 46). Le seul appel vu demande « normal » ; « night » n'est pas demandé en conversation.

Sous-commandes du gros plan

  • CLOSEUP_CONTINUATION : même visage, décor, couleur et image de base ; nouveau texte.
  • SHOW_TEXT : texte affiché 20 images, sans mouvement des lèvres.
  • YESNOCHOICE_BRANCH1 : question « Accept / Reject » (§ 7).

Durée (disquette)

Une image par lecture jusqu'à la fin du texte, puis 40 images (15 si le texte est vide). Une touche coupe l'attente. La version CD a ses propres durées (§ 10).

Yeux et bouche du gros plan

Disquette : la bouche suit le texte, pas la voix. Le texte lu est celui du script tel quel (codes $ non remplacés), mis en minuscules.

Clignement, tiré à chaque image de scène

image des yeux = 12              si rand() × 30 / 32768 = 0 (une fois sur 30)
               = image de base  sinon
si image de base > 20 : image des yeux = image de base (jamais de clignement)

Un clignement dure en général une image (0,1 s), en moyenne toutes les 3 s. Au-delà de 20, l'image de base couvre les yeux, et l'image 12 l'effacerait. Dans les données, 774 répliques peuvent cligner (13 à 20 ou 255), les autres ont les yeux fixes.

Bouche : une lecture par image

« e » + caractère qui n'est pas a..z : consommé aussi → pas de bouche
« e » + « r »   → bouche 6, « r » consommé
« t » + « h »   → bouche 9, « h » consommé
« c » + « h »   → bouche 6, « h » consommé
« h »           → caractère suivant consommé ; bouche de « h » (table)
autre a..z      → bouche = table
autre caractère → pas de bouche
fin du texte    → pas de bouche ; la réplique passe à l'attente

Table « 06891599098769362999252999 », chiffre + 2 :

abcdefghijklmnopqrstuvwxyz
281011371111211109811584111111474111111

Exemple : « Danger is our business. »

7

Question « Accept / Reject » (YESNOCHOICE_BRANCH1)

  • Visage : image de base fixée à 53 (elle remplace l'image des yeux) ; texte de lèvres vide, donc bouche fermée ; pas de clignement (53 > 20).
  • Ouverture : la scène passe en plein écran (0, 0)-(319, 199) ; les bandes noires s'ouvrent en 24 pas (haut : une ligne par pas, bas : deux). L'image ne bouge pas à l'écran : elle est découverte. Les bandes se referment après la réponse.
  • Zone : souris dans x 118 à 279, y 113 à 199 → « Accept Mission », partout ailleurs → « Reject Mission ». Libellé réécrit à y = 175.
  • Effet : réponse rangée pour la partie ; si refus, le curseur avance du mot de la commande.

L'image 53 n'est présente que pour beto, far, muh, walt et tweedly.

Escadre et équipier

  • SELECT_WING : cherche dans GAMEFLOW.IFF la WING dont l'INFO vaut l'octet escadre ; lit son type, la liste PILT (pilotes) et, pour les types 1 et 2, ORDR. Remplit les noms d'équipiers $W, $L, $O. L'octet écran est gardé pour CHOOSE_WINGMAN.
  • CHOOSE_WINGMAN : écran de choix, décor s_wing (écran = 0) ou w_wing (sinon), puis p_wing ; une zone « Select Billy / Gwen / Lyle / Miguel / Tex » pour chaque pilote de PILT ; le pilote choisi remplit $W, $L, $O.

Version CD-ROM : la voix

Lu dans l'OPTTEST.EXE du CD-ROM (sans IDA, listings dans analysis/optest_cd/).

Quand la voix est jouée

Le lecteur lit toujours la chaîne de voix ; une voix absente est une chaîne vide (56 textes). La voix est jouée si les trois conditions sont vraies, sinon le texte est affiché :

  1. la chaîne de voix n'est pas vide ;
  2. un pilote de son numérisé est chargé ;
  3. VOCLIST.IFF a été lu et le premier fichier qu'il nomme existe.

Voix et texte ne sont jamais affichés ensemble : avec voix, le texte n'est pas dessiné. Le fichier est "f:" + identifiant + ".voc" ; la voix suivante de VOCLIST.IFF est préchargée par une tâche de fond.

Durées

CasDurée de la réplique
avec voixjusqu'à la fin du son
sans voix, texte non vide50 images (5 s)
sans voix, texte vide8 images

Espace ou Échap coupe la réplique ; Échap termine aussi la conversation à la commande SHOW_TEXT de premier niveau suivante.

Lèvres avec voix

  • La bouche vient du son (même calcul que les cinématiques, MIDGAME_SYSTEM.md § 6.6) : seuils 95, 78, 65, 42, 25 ; bouches −1, 8, 3, 2, 10, 11 ; une valeur par image de scène.
  • Gros plan : une bouche 10 ou 11 qui suit une bouche 10 ou 11 devient −1 (bouche fermée). Clignement inchangé.
  • Personnage de groupe sans voix : la bouche ne bouge pas dans la version CD (le texte n'avance jamais).

Autres points, gros plan

  • Ordre des couches : libRealSpace dessine la bouche par-dessus les habits ; dans le jeu elle passe avant la coiffure et les habits.
  • Clignement : image 12 une fois sur 30 à chaque image de scène si l'octet vaut 20 au plus ou 255 ; absent de libRealSpace.
  • Bouche : libRealSpace fait tourner les bouches sur l'horloge ; le jeu lit le texte avec les règles du § 6 (code de référence tools/conv_ref/conv_lips.cpp).
  • Image vide (visages incomplets) : ne rien dessiner, ce n'est pas un écart.
  • Accept / Reject : l'image 53 remplace l'image des yeux au lieu d'être ajoutée ; une seule zone « Accept » (x 118 à 279, y 113 à 199).

Lecture du script

  • Format testé avant de parser (ConvData::detectFormat) : sur le premier texte, une première chaîne en forme d'identifiant de voix (vide, ou 1 à 8 lettres ou chiffres) et une suite d'octets valide → CD ; sinon disquette. 241 / 241 justes dans chaque format, au lieu des 29 erreurs de la détection texte par texte sur le CD.
  • Une boucle de premier niveau, un sous-parseur par commande (tools/conv_ref/conv_parser.cpp) ; un octet qui n'est pas une commande est une erreur de parsing. 224 n'est pas une commande : c'est une couleur de texte, lue à la place d'une commande après un décalage.
  • Champs : x, y de GROUP_SHOT_ADD_CHARACTER et de CLOSEUP sont des mots signés petit-boutistes ; YESNOCHOICE_BRANCH1 et YESNOCHOICE_BRANCH2 ont un mot.
  • Décor : 5 octets par élément de BACK, le mot signé y donne la position (0, y + 24).

Scène de groupe

  • Les positions des figures appartiennent à la scène (la même figure a plusieurs positions selon les scripts).
  • Toutes les figures de la scène restent dessinées pendant toutes ses répliques (disquette) ; dans la version CD, chaque personnage qui parle apparaît à sa première réplique.
  • Figurant : image 0 seule ; palette PFIG du premier figurant seulement.

Texte

  • Remplacer chaque occurrence des codes $ ; ajouter $L, $O, $A, $B, $P, $T.
  • Lignes de 30 caractères au plus, coupées aux espaces, à y = 156 + 15 × n.
